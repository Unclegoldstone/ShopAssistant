## 2026-09-28 — Brainstorm：官方文档核对与待定设计点

- FastAPI 官方结论：`StreamingResponse` 接受异步生成器，可用于持续输出；SSE 将使用 `text/event-stream`，生成器内保留可取消的异步等待点。
- LangChain 官方结论：聊天模型可通过 `stream`/`astream` 逐块输出；`with_structured_output(PydanticModel, method="json_schema")` 可要求模型按固定 schema 返回并由 Pydantic 校验；`trim_messages` 支持 `strategy="last"`、`include_system=True`、`start_on="human"` 和 `token_counter="approximate"`，适合本阶段的最简 token 预算裁剪。
- 阿里云百炼官方结论：Qwen 可通过 OpenAI 兼容地址接入 `ChatOpenAI(api_key=..., base_url=..., model=...)`，LangChain 流式调用无需额外设置上游 `stream`；阿里云原生 JSON Schema 只由部分模型支持，因此最终 `.env` 中所填模型必须属于官方列出的 JSON Schema 支持范围，否则 `method="json_schema"` 无法满足固定字段强约束，届时必须停下确认，不能暗自降级到工具调用或普通 JSON 模式。
- 接口候选 A（推荐）：`POST /v1/chat/completions` 接受 OpenAI `messages`，并额外接受可选 `conversation_id`；服务端以该 ID 在内存保存并裁剪上下文，SSE 严格输出 OpenAI chat completion chunk 与 `[DONE]`。优点是能直接验收服务端多轮记忆；代价是请求多一个扩展字段。
- 接口候选 B：完全遵循 OpenAI 请求格式，由客户端每轮重传完整 `messages`，服务端仅对本次 messages 做裁剪，不保存会话。优点是协议最纯；代价是“连续两轮延续上下文”依赖调用方维护历史，不体现服务端会话能力。
- 结构化输出草案：单独提供 `POST /v1/after-sales/extract`，输入售后文本，返回仅包含 `order_id`、`request_type`、`expected_solution` 的 JSON；底层必须调用 LangChain `with_structured_output`，不使用 Agent 或工具循环。
- 当前待用户确认：多轮对话采用候选 A 还是候选 B。确认后才将 brainstorm 标记为定稿并产出 spec。
