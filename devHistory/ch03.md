## 2026-09-30 — Superpowers / Brainstorm 决策：独立调度进程

- 用户关键原话：“采用方案A”。
- 决策：历史对话知识挖取采用独立 APScheduler 进程，不放入 FastAPI lifespan；提供单独启动脚本持续调度，同时提供调用同一 service 的一次性执行命令，用于验收、人工补跑和故障排查。
- 运行边界：调度进程按配置周期分批读取尚未挖取的历史会话，限制同一任务并发为 1；FastAPI 是否重载、多 worker 或停止，不影响调度器自身生命周期，也不会因为 Web worker 数量重复启动任务。
- 官方接口核对：APScheduler 官方建议纯调度程序使用异步 Scheduler 的前台 `run_until_stopped()`；任务可限制最大并发，并由 Interval/Cron trigger 周期触发。具体版本和 API 将在实施前锁定并以安装后的官方版本实测为准。

## 2026-09-30 — Superpowers / Brainstorm 决策：采用二级去重

- 用户关键原话：“采用这个二级去重方案”。
- 第一级：对规范化后的 `category + questions + answer` 计算稳定指纹，先消除完全相同或仅空白/标点差异的重复记录。
- 第二级：使用 BGE-M3 dense 向量为暂存记录寻找高相似候选，再由现有阿里云 LLM 以结构化输出判定“可合并 / 冲突 / 独立”。只有问题与答案语义均等价时才合并 questions；答案冲突、政策版本差异或判断不确定时均保留两条。
- 全局边界：候选范围同时覆盖本轮全部暂存记录和已经入库的 `knowledge_chunks`，但采用分批候选比较，不把全部知识一次性塞入 LLM；判定与合并结果保留在暂存记录中，便于追溯和重跑。
- 当前阶段：已解除核心数据形态与去重歧义，开始核对文档切分、Milvus dense 搜索及幂等写入官方接口，并形成完整设计 spec。
